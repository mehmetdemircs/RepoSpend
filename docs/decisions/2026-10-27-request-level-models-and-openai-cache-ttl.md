# Price Codex per request and normalize OpenAI cache-write TTLs

## Context

Codex sessions can switch models mid-session, and OpenAI bills cache writes by TTL (30-minute and 12-hour) and reprices whole requests above 272K input tokens. Pricing an entire session under its first model overcharges the cheaper model's share, flat `cache_creation_input_tokens` cannot distinguish the OpenAI TTLs, and session totals cannot pick a context tier.

## Decision

Track the active declared model as session records stream by and attach it to each extracted usage record. Per-turn `last_token_usage` deltas and direct usage records become per-request slices with their own model and request input size; cumulative-only sessions collapse to one aggregate slice with no record model and an unknown request size. Sessions expose `modelUsage` slices (model, request count, token buckets, slice cost) so model rollups and filters reflect real per-model work without duplicating sessions or token counts.

Extend the request-context rule set from Haiku 5.5 to the GPT-6/6.1 cards at 272K input tokens, then to the published GPT-5.x Standard cards (5.6 Sol/Terra/Luna, 5.5, 5.5 Pro, 5.4, 5.4 Pro — mini/nano have no published tier). A known request size selects the exact `-long-context` card (a RepoSpend rate card, not a provider model ID). Unknown request sizes keep short-context rates with an `assumed_short_context_rates` assumption; saved tables missing the long-context card fall back to base rates with `missing_long_context_pricing`. Exact custom rows always win, and models that inherit an older-generation card are priced against the rule's own base row so an invalid base card stays unpriced rather than billing a different generation. The rule registry is the single authority for base→long-context mapping; pricing API responses serialize it (`contextRules`) so the Settings UI resolves alias bases and shared long-context cards without re-deriving naming conventions.

Normalize OpenAI flat and nested cache shapes (`cached_input_tokens`/`input_tokens_details.cached_tokens`, `cache_write_tokens`/`input_tokens_details.cache_write_tokens`, `cache_write_tokens_details.ttl_30m_tokens`/`ttl_12h_tokens`) into shared cache buckets through types, aggregation, exports, and the pricing editor. Unclassified writes keep billing at the generic cache-write rate. The Codex parse cache moved to `parse-v2`/`codex-session-v2` because the stored breakdown shape changed.

## Consequences

Mixed-model sessions bill each request at its own rates (a recorded audit case moved a two-request session from $3.00 at the first model to $1.80 across both). Cached Codex breakdowns from older versions rebuild once. Aggregate-only sessions still estimate, but carry an explicit assumption instead of an invented tier. Selecting models in the filter projects only the matching `modelUsage` slices into every accounting surface — summaries, groups, rollups, exports — while keeping one session row per filtered session; model top-repository rankings use the same slices. Sensitive local read endpoints reject non-local Host headers for DNS-rebinding protection on both literal and percent-encoded GET/HEAD paths while CLI and health checks keep working. An intentionally re-priced canonical card stays flat above the long-context threshold unless the user also saves their own `-long-context` card. The runtime floor moved to Node 22.12 because @fastify/static 10 depends on the ESM-only `content-disposition` 3; the packaged CLI and dashboard were verified on Node 22.12.0. No new dependencies, provider calls, or access to source-client files are required.
